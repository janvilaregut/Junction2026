# Graph-directed review

Select a changed C# function in the graph and choose Review this spot. Quick, Standard and Deep use the existing 90/300/900-second and 25k/100k/250k-token ceilings. Standard is the default for independent reconstruction. Quick does not reconstruct alternatives and cannot establish the new node-level evidence gate.

Population demand is the same heuristic in every profile: min(4, 2 + ceil(log2(G)) + H), with zero candidates for no executable groups. G counts behavior groups; H counts high-risk groups. The admitted count is the minimum of that demand, the profile cap (0/2/4), the time cap and the token cap. Time reserves 60 seconds then estimates serial validation plus half the build time (two model slots); tokens reserve 18,000 then estimate 10,000 per candidate. Deep permits at most two descendants, six total patches and three final missions. Standard has one final mission. These are scheduling heuristics, not statistical confidence estimates.

Continue investigation reuses intact contract, tests and usable candidates while opening a new bounded budget; inherited and new token consumption are recorded separately. Invalid candidates are not restored as successes. Review whole PR selects all eligible changed functions. The result card exposes score components, pending evidence, all candidate statuses, Entire capture status and observed cost.

The server resolves node IDs, pins base/head and maps them to historical Roslyn behavior groups. Only selected groups get candidate missions; candidate source blocks use the historical base. Context and the existing relevant regression suite remain available. Two model families construct independently, debate hypotheses, and the existing runner compares attacks against the original and candidates. Entire and the privacy gateway are inherited from the full pipeline.

Review next selects the highest-priority remaining function, one bounded review at a time. It does not launch an unlimited swarm. Selection does not shrink the denominator.

The progress metric is floor(100 * sum(weights of verified nodes) / sum(weights of changed executable nodes)). Weight is 1 + 4 * impact, a declared policy rather than a calibrated probability. Documentation, tests, removed code, types and equivalence-proved nodes are outside this executable reconstruction measure. The UI also shows failures and pending nodes. Empty scope has no percentage. A partial graph cannot obtain 100%.

A node earns support only with grounded expectations supported by the judge, an admitted targeted attack executed on the original and at least two built alternatives, a completed passing original regression suite, and a completed semantic verdict. Node support additionally requires a Roslyn-injected unique exception in a disposable original copy: the same admitted scenario must pass on the original and fail with that marker after instrumentation. Source and Git index are restored in finally. This establishes test sensitivity to a method failure, not full branch coverage. Unsupported probes and timeouts remain pending. The gate never converts model agreement or manual read marks into execution evidence. A candidate-only failure does not condemn the original. Confirmed original failures block support. New incomplete investigations can reduce the percentage.

Reports retain contract, attack, execution and session artifacts. Graph progress checks artifact integrity, code/base, requirement context and analysis version. The key also includes OS, Node, configured .NET root, locally installed SDK versions and relevant runner/probe source hashes. Restored dependencies are bound to execution evidence. Arbitrary external service or machine-state changes still require a fresh review. Scoped reports cannot sign off the entire PR with unreviewed scope. Patches are proposals for review, not automatically applied fixes. Applying any change requires a fresh review of its commit.

Current limitation: C# runner and Tieto #2283 adapter. Other languages retain the existing full-review behavior; graph-directed execution rejects unsupported nodes. No claim that the available tests exhaust a function's behavior. One automatic repair proposal may run after a repeated original failure when at least 90 seconds remain. It is applied only to a scratch copy of the original and must pass the admitted tests plus the relevant suite. Downloading/applying the patch and merging remain human actions. No calibrated probability of correctness.

Validation: test/graph-review.test.js covers weighting, denominator integrity, invalidation, historical mapping, zero tests, timeout, missing alternatives, incomplete judgment, candidate-only failures and malformed source escaping. Existing budget, score, runner and review tests also run. Windows fixtures now use portable names and Git-index symlink controls; one POSIX wrapper-only test is skipped explicitly on Windows.
