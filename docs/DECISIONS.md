# Decision log

Design decisions made while building Katse, in the order they came up. Each one says what was decided, why, and what was rejected. Failure modes that triggered a decision are in [LESSONS.md](LESSONS.md).

| # | Decision | Why | Rejected alternative |
|---|---|---|---|
| 1 | **Reproduce instead of read.** The concept is built on reproducing the change | Line-by-line reading doesn't scale with agent-written code. Reproducing does, because generating is cheap | An agent reviewer that reads the diff and gives an opinion, which is exactly "the AI said it was fine" |
| 2 | **The tool never approves or merges.** It only merges into a throwaway copy to test | The challenge requires a named human accountable for every change | Auto-merge when everything is green |
| 3 | **Readable rules instead of a score.** The lane comes from named rules, and the report shows which fired and which didn't | The challenge rejects risk scores nobody can explain | A confidence percentage per PR |
| 4 | **Don't keep "the best" rebuild.** Rebuilds are evidence for reviewing the PR, not replacements | Picking another version automatically would be the AI approving and rewriting | A tournament between versions and merging the winner |
| 5 | **Agreement between rebuilds only directs attention.** It never counts as proof | Rebuilds from the same model share blind spots and can agree on the same mistake | Majority vote |
| 6 | **The number of rebuilds depends on risk, not lines** | Rebuilds are the expensive step. We don't call it "statistically significant" because rebuilds aren't independent | A fixed N, or N proportional to diff size |
| 7 | **A PR is a branch ahead of its base.** Incoming = remote branches, outgoing = local unpushed branches | Works with any git repo, without a provider API or credentials | Integrating only with the GitHub API |
| 8 | **The base is detected from `origin/HEAD` and always shown.** It can be changed in settings | In the challenge repo the real base wasn't `master`: branches came from a branch 235 commits behind | Assuming `main` or `master` |
| 9 | **Check the base before blaming the PR.** If something fails with the PR, try it without | The first run sent back a PR for a test project that didn't compile without the PR either | Treating every build failure as the change's fault |
| 10 | **What doesn't run is said.** A test the sandbox can't run shows as "not run" and creates a question | Staying silent is the same as calling it fine | Ignoring projects that don't compile |
| 11 | **Rebuilds work on a copy with no history.** Not a worktree: an export of the base commit with a fresh repository | In a worktree the agent can see the PR branch with `git log --all` | Git worktrees for everything |
| 12 | **Three isolation layers for agents:** history-free copy, OS sandbox, and a check of the original repo before and after | In the first run the agents worked inside the original repo (Lessons 1) | Trusting the process working directory |
| 13 | **If one agent touches the original repo, all rebuilds are discarded** | Their work can no longer be called independent | Discarding only the guilty rebuild |
| 14 | **Models only word things.** The judge words questions and the assistant answers from the report. None has a verdict | A hallucination can then only produce a badly worded question, never an approval | A judge that decides whether to approve |
| 15 | **A new test proves itself by failing without the change.** The PR's tests are run on the base | A test written alongside the code may always pass and prove nothing | Accepting that the PR's tests pass with the PR |
| 16 | **Seeded defects measure two things at once:** whether the PR's tests have teeth, and whether the review would catch a known bug | The only reviewer-quality measure available without waiting for production incidents | Measuring only activity (comments, time) |
| 17 | **Cross-tests between the PR and the rebuilds.** A PR test that other implementations of the same requirement fail pins something the requirement doesn't say | Turns "the rebuilds differ" from a text comparison into executed evidence | Comparing only diff text |
| 18 | **No saved prompt, less confidence.** With Entire the original prompt is used; without it, the issue text, and the report says so | Provenance is part of the evidence. The challenge branches don't carry it | Treating a change with provenance the same as one without |
| 19 | **Signing costs effort.** Answer every question, confirm what was read, write the accepted risk | Reduces automation bias, i.e. signing without looking | An "Approve" button |
| 20 | **Trust is per area and starts on probation.** Earned with five signed changes without escapes, withdrawn by one escape | The challenge asks for trust earned from track record and withdrawn after escapes | Global trust in the tool |
| 21 | **Node with no framework and a UI with no build step** | Starts with `npm start` on any hackathon machine | A frontend framework and a database |
| 22 | **Results are stored outside the user's repo.** The only optional write is `git notes`, on request | "Your repository is never touched" has to be true | Writing the report inside the reviewed repo |
| 23 | **A rebuild only counts if it stands on its own:** changes product code, compiles and passes its own tests | Agents ran out of quota midway and their partial work counted as "divergence" (Lessons 2) | Counting any rebuild that changed a file |
| 24 | **Pre-flight check of every agent** with a minimal request. If the user didn't pick agents, a failing one is replaced by the next | Avoids wasting minutes on an agent without quota or session, and records why it didn't take part | Finding out when the agent fails midway |
| 25 | **If every valid rebuild is from the same model family, the report says so** under "not checked" | A stated reason to distrust agreement | Treating three rebuilds of one model like three of different models |
| 26 | **Patch-based fake agents** (`KATSE_FAKE_AGENTS`) to test the pipeline without spending quota. Their results are stored apart and never shown as agent rebuilds | Comparison and cross-test logic must be testable deterministically | Testing only with real agents |
| 27 | **Katse visual identity** (eye logo, dark `#0D111C` / `#171D2C`, violet `#B7A4FF`, Geist + IBM Plex Mono). The assistant is the eye: it looks and shows, it doesn't decide | The team's identity in `visual/`. The eye fits the idea | Keeping the first prototype's cyan sphere |
| 28 | **Text-only calls are isolated too:** empty folder, read-only agent, write-denied sandbox | A model asked only for text edited the reviewed repo (Lessons 3) | Trusting that a model asked for text won't use tools |
| 29 | **The original repo is checked before and after the whole review**, not just the rebuild stage | A check limited to one stage can't see the others | Watching only the agent stage |
| 30 | **Rewind: remove each code change one at a time and run the tests.** If nothing fails, ask what justifies that change | From the team's own discussion ("drop this step"). Deterministic and cheap. On #2283 it found a change (line 985) no test depends on | Rebuilding intermediate steps with a model |
| 31 | **Rebuild count by formula** (first version: `min(6, 1 + change groups + high-risk groups)`), each rebuild with a different mission. *Superseded by 35* | Every rebuild exists for a reason you can say out loud | A fixed N, or proportional to lines |
| 32 | **Three-way recommendation** above the lane: *request changes*, *insufficient evidence*, *ready for human approval* | It's the first thing the person needs; the lane says how much to read, the recommendation says what it looks like | Only the lane |
| 33 | **The signature expires if the branch moves.** The list and report show "signature expired" and which commit it was for | From the team's discussion ("you approved Tuesday's document"). A signature is for one commit | Signature per branch |
| 34 | **Four layers, cheapest and most certain first:** privacy, maths, reproduce, you | Each layer shrinks what the next one (and the human) must handle, and AI is used only where maths can't decide | Sending the whole diff to models first |
| 35 | **Sample size `n = min(4, 2 + ⌈log₂ G⌉ + H)`**, then capped by the chosen depth, time to build *and test*, and tokens left | 2 is the floor for a disagreement; log G spreads the error budget over G behaviours; H adds one per high-risk behaviour; correlated agents saturate, so we cap at 4 and buy diversity | More agents of the same model |
| 36 | **Three depths: Quick (90 s / 25k tokens, no rebuilds), Standard (5 min / 100k, ≤2 rebuilds), Deep (15 min / 250k, ≤4 + 2)** | The owner chooses how much compute a change deserves. Budgets are reserved before each call and reconciled with provider usage | One fixed pipeline |
| 37 | **The maths layer has no model in it.** PageRank, proofs, entropy and deterministic checks decide colour and size | "No AI grading AI": same input, same answer. No model can turn a node green | Asking a model to rate risk |
| 38 | **A judge must quote the requirement sentence that decides a difference**, checked by plain string search. No quote, no verdict | Prevents made-up rules | Free-text judge opinions |
| 39 | **Privacy is fail-closed.** A local Gemma 4 scans and aliases code before any cloud call; if it can't finish, nothing is sent | Banks will not send raw code to a cloud model. A privacy failure must block, not leak (Lessons 12) | Best-effort redaction |
| 40 | **Gemini Decisions can only add doubt.** Adopted only above 0.8 confidence; otherwise deterministic rules apply. It never decides the verdict | A discriminative model is useful for focusing attention, dangerous as an approver | Letting a model pick what to skip |
| 41 | **Node probes:** before a function counts as supported, Katse injects a unique failure into it in a throwaway copy; the same test must turn red | Proves the test is sensitive to that method, not just green | Trusting a passing test |
| 42 | **Weighted progress `Σw(verified) / Σw(changed)`, `w = 1 + 4·impact`, with a fixed denominator.** Reading or model agreement never moves it | Progress must mean verified behaviour, and selecting fewer nodes can't inflate it | Counting nodes "looked at" |
| 43 | **A candidate-only failure is an audit note, not a defect of the PR** | The verdict is always about the original PR (Lessons 13) | Condemning the PR when an alternative fails |
| 44 | **"Continue with Deep" reuses verified work** (contract, admitted scenarios, patches) after checking hashes, and re-runs the tests | Deeper review shouldn't throw away evidence, and the environment must be re-observed | Starting over every time |
